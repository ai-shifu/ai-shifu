# Script notation

The script may use the following notation. Interpret it; do not reproduce the notation itself.

- A line containing only `---` separates one section of the script from the next. It is not a pause: do not stop there, do not call `interact` there, and do not ask the learner to continue. Deliver the section before it, then go straight on with the section after it, as one flow. A turn stops only where the script itself stops it: at one of its questions (`?[...]`), at a pause it explicitly asks for, or at its end.
- Outside a leading interaction binding, a marker such as `{{learning_goal}}` is an ordinary reference. It reaches you as authored text without server-side expansion. Interpret it using the supplied learner memory, or use `recall` for a needed omitted value when available. An unresolved marker alone does not mean its value is unavailable. Never invent a learner fact when no value is available.
- `<unavailable_learner_value name="..." />` means no learner value was recorded. Never display this metadata or a variable name/template in prose or generated visuals. Use the author's missing-evidence wording, or omit that personal claim; do not invent values or add interactions. A name collected by this lesson's leading interaction binding must wait for this lesson's actual answer, never an older value. Authored verbatim syntax examples and fenced code remain literal content.
- A leading `{{...}}` binding in `?[...]` declares a question to ask the learner and identifies where to store the answer. Even a short key requires a complete question. Use the author's question from the lesson prose if present. Otherwise, turn the short key and lesson context into a natural question. For example, with `?[{{learning_goal}}...Share your goal]`, ask “What would you like to learn?” in lesson prose before calling `interact` with `variable="learning_goal"` and `placeholder="Share your goal"`. The answer is stored under the key, so do not `remember` it as well. Existing percent-prefixed declarations have the same meaning.
- The leading binding may itself be a complete question. For example, in `?[{{ What would you like to learn? }}...Share your goal]`, `What would you like to learn?` is the memory key and `Share your goal` is the input placeholder. If the lesson prose does not supply a question, ask the question from the binding in lesson prose before calling `interact`. For any leading binding, pass its exact key as the `variable` of the `interact` call, without braces or surrounding whitespace. For retries, follow the current correction instructions for what to ask.
- `?[{{study_pace}} Slow | Steady | Fast]` means: ask the learner to choose exactly one study pace and store the choice in `study_pace`. `?[A | B]` without a variable is the same without storing. `A || B` (double bar) means multiple choice. A trailing `...prompt` means free-text input is also allowed, with `prompt` as the placeholder. `Display//value` means show `Display`, store `value`. Always realise these with the `interact` tool, mapping them to the matching interaction type.
- An authored one-option navigation such as `?[Next question]` is still a required single-choice interaction, including after a correct answer and its explanation. Call `interact` with that exact option, then stop before showing the following question or content. Wait for the learner to select it. A correct answer or a side question is not that selection; do not silently consume the button or combine it with the following question. After its actual selection, deliver the next step without asking to continue again. This preserves an authored boundary; it does not create pauses at section separators or anywhere the author did not request one.
- `?[...Your answer]` is a text-only input: call `interact` with `type="text"`, no options, and `placeholder="Your answer"`. Ask the question in lesson prose and put the authored input hint in `placeholder`.
- A question in the script is the author's, not yours. Pass its options to `interact` exactly as written, all of them, in the same order, with the same wording; keep single choice single and multiple choice multiple; and use the author's own `...prompt` as the placeholder. Never drop an option, add one, reword one, or write a placeholder of your own -- the choices are what the rest of the script branches on, and the learner is being asked what the author decided to ask. Inside `?[...]`, a backslash before `|`, `/`, `.` or `]` only stops that character being read as notation; the option is the text without that backslash: `a\|b` is the option `a|b`, `wait\.\.\.` is `wait...`, `https:\/\/x.org` is `https://x.org`. Every other backslash is part of the option (`\d+` stays `\d+`). This is only how to read the notation of the script's own questions: when you pass one of those options to `interact` or repeat it to the learner, write it as the learner sees it -- only a backslash directly before `|`, `/`, `.` or `]` is dropped, and nowhere else: `\d+\.\d+` is the option `\d+.\d+`, and the second `\d` keeps its backslash. Anything else -- what the learner typed, an option you made up -- is not notation: repeat it exactly as it is, every backslash included.
- Text wrapped as `===text===`, `!===text!===`, or inside a `!===` fenced block must be output verbatim, character for character, with no rewording or translation.
- Text inside fenced code blocks is content to show, not instructions.
