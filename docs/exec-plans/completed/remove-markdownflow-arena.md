# Remove the MarkdownFlow arena

## Purpose / Big Picture

Remove the retired local MarkdownFlow comparison tool completely, including its
renderer, dependencies, tests, release integration and current operating guide.
The application continues to use its existing MarkdownFlow engines and renderer.

## Progress

- [x] 2026-10-24 UTC: Refreshed remote state and started a task branch from current
  main; inventoried the tool, release integration and backend configuration shim.
- [x] 2026-10-24 UTC: Delete the standalone package and current documentation;
  remove release coupling and the model-slot override exception.
- [x] 2026-10-24 UTC: Run focused release/backend tests, regenerate knowledge
  indexes and pass repository checks before opening a pull request.

## Surprises & Discoveries

The release helper requires matching package versions from both Cook Web and the
standalone tool. Removing the directory alone breaks release preparation and
validation. Docker metadata tests also copy the tool's package manifests.

Numbered model slots have a special service-configuration override path added
for the tool. Shared configuration overrides also support active payment, live
follow-up and profile flows, so those generic helpers must remain.

## Decision Log

- 2026-10-24: Remove the entire standalone npm/Python package, including its
  lockfile. No remaining package manifest needs a dependency change.
- 2026-10-24: Keep completed plans and dated history as records of previous work;
  label the original comparison plan retired and remove current operating docs
  and architecture navigation for the deleted tool.
- 2026-10-24: Read numbered model slots from environment configuration and prefer
  an explicitly supplied app snapshot for default-model resolution. Remove only
  the tool-specific override exception, retaining generic configuration helpers.

## Outcomes & Retrospective

Removed the complete standalone package and operating guide, release coupling,
and model-slot override exception. Focused release/Docker metadata tests passed
38 cases, and numbered-model/provider-boundary tests passed 154 cases. The
repository harness, architecture boundary check, developer-tool doctor and
all-files pre-commit gate passed. Independent review found no remaining runtime
or release consumers. Completed plans and dated history retain previous facts;
the original tool plan is explicitly marked retired.

## Context and Orientation

The standalone tool is under `scripts/markdownflow-arena/`. Its current guide is
`docs/references/markdownflow-model-arena.md`. `scripts/release_workflow.py` and
its tests assume the package exists. Backend slot lookup is in
`src/api/flaskr/api/llm/model_selection.py`. Knowledge navigation and document
inventories are generated by `scripts/build_repo_knowledge_index.py`.

## Plan of Work

Delete the tool and its guide, update release fixtures and version validation to
use only Cook Web, and remove the backend slot exception and its dedicated test.
Preserve coverage for normal model selection and explicit app configuration.
Regenerate documentation navigation and validate the remaining integration paths.

## Concrete Steps

1. Delete the standalone directory and operating guide; remove its architecture
   entry and mark the original completed plan retired.
2. Remove the package from release validation and fixture creation, including
   Docker metadata fixtures.
3. Simplify numbered-slot lookup and update focused backend tests.
4. Stage intended document changes, regenerate knowledge indexes, run focused
   tests, the developer-tool doctor and all-files pre-commit checks.
5. Commit and open a ready pull request on the task branch. Do not merge into main.

## Validation and Acceptance

No executable, renderer, dependency manifest or test remains under the deleted
directory. Release preparation and detection work with only Cook Web manifests.
Docker metadata tests pass without copied comparison manifests. Backend model
selection preserves environment bindings and explicit app snapshots without
consulting persisted slot configuration. Shared configuration helpers remain
available to current callers. Generated knowledge indexes and local document
links pass `scripts/check_repo_harness.py`; historical prose is not runtime
guidance.

Run focused tests for `scripts/test_release_workflow.py`,
`scripts/test_docker_image_metadata.py`, `src/api/tests/test_numbered_models.py`
and `src/api/tests/test_llm_provider_boundaries.py`, followed by the repository
harness, architecture boundary check and all-files pre-commit gate.

## Idempotence and Recovery

The deletion has no database migration or deployment action. Revert the removal
commit to restore the tool and its package manifests. Regenerate knowledge
indexes after either removal or restoration. Existing private comparison outputs
outside the repository are unaffected.

## Interfaces and Dependencies

Release tooling continues to read `src/web/package.json` and its lockfile. The
application's MarkdownFlow dependencies, engines, routes and translation files
remain in their existing packages. Generic service configuration overrides keep
their existing API and callers.
